# 当前证据支持的论文主线

建议定位：**计算预算约束下、面向世界模型的双侧 FP4 残差修复与执行协同设计。**

中心问题是：FP4 为减少存储和增加矩阵吞吐提供条件，但直接量化损失较大；恢复精度需要额外工作，而错误的修复分配、在线准备和执行碎片化会消耗算力收益。因此需要同时决定“表示什么残差、修哪里、如何实际执行”。

## 叙事顺序

### 1. 低比特存储不等于低成本的高质量推理

区分两种现有路线：权重低比特、激活高精度的 W4A16，以及原生 W4A4。前者避免 A4 误差，但不能直接获得原生 FP4×FP4 MMA 的峰值收益；后者利用原生低精度矩阵计算，但需要处理双侧量化误差。

AWQ 不能被定义成“一定更慢”：本轮 AWQ-lite/Marlin 的反量化已融合到 GEMM，是否加速依赖具体形状、带宽和实现。ARCQuant 与 SharQ 更不能归入高精度反量化路线。ARCQuant 使用增强残差通道；SharQ 使用 sparse FP4 主路径与 dense FP4 残差路径，二者都已讨论残差与高效执行。[ARCQuant 官方实现](https://github.com/actypedef/ARCQuant)、[SharQ 官方实现](https://github.com/actypedef/SharQ)。

因此 novelty 不能只是“第一次用 FP4 表示量化误差”或代数展开本身。我们的区别需要落在世界模型的双侧误差、生成投影和 attention 的联合预算、W1 支持并集存储与可执行的修复调度上，并用匹配对照验证。

### 2. 将 FP4 计算余量用于双侧残差修复

设 X0、W0 是解码后的 FP4 基础表示，Xr、Wr 是实际残差再编码后的 FP4 表示：

`Y_hat = X0 W0ᵀ + Xr W0ᵀ + X0 Wrᵀ [+ Xr Wrᵀ]`

这不是原矩阵乘法的精确恒等式：Xr/Wr 的再量化仍有误差。四项是高预算质量锚点；三项舍弃交叉项，能否接受取决于算子、输入和完整轨迹。即使峰值 FP4/BF16 比是 4，四项也只能在忽略 packing、访存、归约及未替换部分时获得“矩阵算术可能接近 BF16 成本”的动机，不能直接推导实测等速。

16 个既有 development 场景、每场景两种子，相对同输入 BF16 的 LPIPS 均值：

| 方法 | RBench | PAI-Bench |
|---|---:|---:|
| 普通联合 W4A4 | .303164 | .237846 |
| FP8 | .107015 | .055055 |
| 全量三项，FP4 attention | .066648 | .041128 |
| 全量四项，FP4 attention | .068889 | .035368 |

这有力支持“双侧修复可以恢复输出一致性”，以及高预算均值能够优于 FP8。它不是独立最终集结论，也不是比 BF16 更好的真实视频质量。三项在 RBench LPIPS 略好，四项在 PAI 更好；交叉项不能写成普遍无用。不同 QK/PV 消融也显示收益不一致。

### 3. 从全量恢复转为预算约束的非均匀修复

W1 是离线、常驻的残差；Ar 是当前输入决定的在线残差。两者成本不对称：少存 W1 可以减少模型大小，减少 Ar 可以减少在线工作，但二者误差会耦合。总 MMA 预算、W1 并集大小、packing 和 scratch 必须分别约束，不能仅比较修复百分比。

2× 预算下的完整方法比较支持“组合分配比只修一侧更有效”：

| 配置 | 请求 MMA/C0 | RBench LPIPS | PAI LPIPS | W1 MiB |
|---|---:|---:|---:|---:|
| 单 A 修复 + 全 ACT2 attention | 2.000 | .246027 | .167524 | 0 |
| 单 W 修复 + 全 ACT2 attention | 2.000 | .277081 | .205519 | 756.0 |
| 当前 2× 联合配置 | 1.928–1.947 | .149061 | .096039 | 70.88 |
| 当前 1.5× 联合配置 | 1.491–1.500 | .182627 | .113919 | 35.16 |

这是**同整请求预算上限下的完整策略对比**。联合方案还改变了 W0/修复分配和 attention 项数；不能单独据此说差距全部来自 head finding 或增加某一 W tile。若要做纯 W/A 因果归因，必须固定 W0、attention 和所有其他支持。历史 BF16 attention 的线性层单侧/双侧消融可作补充，但也不能混入联合 FP4 速度结果。

当前三档的含义可以固定为：1.5× 偏速度和低 W1 存储；2× 保留更多双侧修复；2.5× 偏输出一致性。不是“各档都优于一切 baseline”。当前 1.5× 未全面超过 AWQ/ARC100，2.5× 也未通过原先超过 FP8 的完整门槛。

### 4. 稀疏应作用于修复，而不是删除基础语义计算

保持所有 attention base blocks，不删基础 GEMM，不复用旧 step 输出，不减少生成步数。候选配额可以依赖层、阶段、head、QK/PV 方向，但激活选择始终读取当前输入。离线预编译支持上界，使任意在线选择都不会突破请求预算；W1 只存执行所需的支持并集。

head 和 AR–DM 趋势目前适合作为**候选生成依据与结构动机**。注意力权重较小不自动等于对应修复的输出收益小：还受 V、softmax、后续层和残差相关性影响。应对相同预算做修复开关干预，用完整生成质量确认。

当前更复杂的跨阶段联合 schedule 未通过两个数据集的全部均值 guard；新“可表示残差收益 × 通道敏感度”选择器也失败。不能把这两项写成已经验证的独立贡献。现有 2×/2.5× attention 仍为全三项修复，尤其不能将其收益归为大量 per-head attention tile skip。

### 5. 用系统实现把预算变成真实节省

计算减少需要传递到少执行修复 MMA、少写残差、少存 W1，而不是只减少理论计数。共享 FP32 累加器、合法情况下复用 packing、联合 Graph 和外围融合，是把算法预算变成部署收益的必要条件。

新分项结果表明：BF16 可替换生成投影/FFN 只占约 42.3% 的累计 GPU kernel 时间；ARC/SharQ 的原生 GEMM 本身较快，但当前适配中的准备和调度成本较大；我们的固定质量执行优化减少外围工作，吞吐增加约 11–13%。[完整 breakdown](REPORT.md)

目前不能写“已经逼近峰值”：四个代表性修复 GEMM 的 Tensor pipe 活跃指标为 13–49%，部分 CTA 数低于 SM 数，修复 FP4 attention 也比 BF16 FlashAttention 慢。Amdahl 效应用来解释端到端与算术峰值的差异，不能代替内核效率验证。

## 哪些贡献已支持，哪些仍需补证

| 主张 | 当前证据状态 | 合理写法 |
|---|---|---|
| FP4 双侧残差恢复完整轨迹一致性 | 高预算 development 效果明显 | 机制证据；须补独立冻结评价 |
| 低预算联合配置优于已有单侧 2× 配置 | 两数据集开发均值支持，成本已核算 | 整体策略优势，不拆成未配平的单机制因果 |
| W1 支持并集压缩减少部署存储 | 真实压缩资产和运行期统计支持 | 分开报告投影权重、模型常驻 state、Graph/scratch 峰值 |
| 固定质量下融合/Graph 改善执行 | 96 个完整输出逐位相同，五轮计时支持 | 系统收益，通用优化与 FP4 专属优化分列 |
| outlier 联合选择稳定改善 W0/W1 | 当前不足；2.5× 若干候选退化 | 搜索维度/负结果，不能当主贡献定论 |
| 更复杂 head/step schedule 稳定胜出 | 当前 guard 未过 | 结构启发候选，不宣称已证明最优分配 |
| 低预算全面超过 FP8 | 未达成 | 保留 FP8 为强对照并报告差距 |
| 各设备已达到延迟 Pareto 最优/峰值 | 未证明 | 已搜索配置的资源取舍；独占和跨设备另测 |

outlier 的独立 validation 中，2× Four-over-Six 尺度候选相对 RTN 的 ΔLPIPS 均值为 RBench −.005931、PAI −.006068，但 95% 区间分别跨零；多比较 guard 也未通过，最终测试没有晋级候选。当前公开三档资产不包含 mandatory outlier 移除。局部输出 NMSE 优势不能改写成完整生成的稳定增益。

## 可用于正文的表述草案

> 原生 FP4 提供了一种以低比特矩阵计算修复量化误差的机会，但单纯减少位宽并不能保证世界模型的输出一致性或请求加速。我们将生成投影和 attention 中的量化恢复组织为双侧残差修复，并区分离线权重残差的常驻成本与在线激活残差的输入依赖成本。在保持全部基础计算和生成步数的条件下，我们对完整请求的修复计算与权重支持进行联合约束，通过块级支持和执行融合控制实际额外工作。机制实验显示，全量修复显著改善普通 W4A4 的输出一致性，而非均匀联合配置在较低预算下优于已有单侧修复配置。系统实验进一步表明，在线准备与执行组织是决定 FP4 收益能否传递到端到端推理的重要因素。

草案不预设所有低预算都超过 FP8，也不声称简单残差展开是首创。投稿前的关键缺口是：冻结一个真正有增益的预算分配机制，完成独立数据评价；将 head/阶段干预、权重表示改进与通用融合的贡献分开。若 outlier 或复杂 schedule 继续失败，应缩小主张，而不是用未经验证的解释补足三个“贡献点”。

所有 PSNR/SSIM/LPIPS 均为相对 BF16 输出的一致性指标，不是物理合理性、动作任务成功率或人类偏好指标。本轮机制质量主要来自 16 个已使用 development 场景；不能写成已经完成 72 个独立最终场景的整套验收。
