# FFN 通道块与权重块修复：2026-09-07

建议沿用 dense W4 基座，优先尝试**离线选定的 K128/K256 激活通道块＋少量离线 N128×K 权重残差块**。激活支持在所有输出 N 块之间共享，修复尽量在同一 K 循环内复用 W0；权重残差使用压缩块存储。当前结果支持这个方向，但收益尚不足以自动替换 full ACT2 默认配置。

## 实验边界

- 本地 Cosmos3-Nano BF16 revision `411f42a8fdfb8c5b2583cb8786e0938f49796eaa`。
- 使用社区 AWQ revision `95b7d2328f8ff8667f2f9c55b03d1af122005c16` 的 prescale D，但 W0 是对当前本地 `BF16(W/D)` 重新 RTN 打包。**没有使用社区已经优化好的 packed W4，不能据此宣称超过 AWQ。**这样可以明确 W1 修复的是已知 W0 相对同一 BF16 权重的残差。
- 层 0/24，gate/up/down 共 6 个矩阵。AV 的 steps 0/17/34、每步 128 行用于离线选块；robot026 的相同步、每步 128 行用于 18 组线性层回放。这些都是此前已经观察过的开发输入，非全新 held-out 集。
- 另有 6 组完整 FFN 回放：候选 gate/up 的输出经过 SiLU 和逐元素乘法，再作为该候选 down 的输入，没有给 down 注入 BF16 教师激活。参考为当前 BF16 FFN 运算。
- 当前 BF16 重新计算的中间激活与历史 down 捕获仍有 0.00476–0.00543 相对 L2 差异。因此本实验是相对当前 BF16 运算的局部 FFN 一致性评估，不是历史模型轨迹的 bitwise 重放。
- 性能：物理 GPU 3，RTX PRO 6000 Blackwell SM120，PyTorch 2.11.0+cu130/Triton 3.6.0，共享 GPU。M512 通过重复真实的 128 行构造，用于形状计时，不作为新的精度样本。

## 稀疏对象和误差分解

设经过 prescale 的激活为 A，离线变换权重为 W，量化成 A0、W0，残差量化为 A1、W1：

```
Y ≈ A0 W0ᵀ + (A1 ⊙ SA) W0ᵀ + A0 (W1 ⊙ SW)ᵀ
```

- `SA`：每个 M128 行组共享的 K 通道块支持，在所有 N 输出块上复用。
- `SW`：离线选中的 N128×K128 或 N128×K256 权重残差块。
- 第四项 `(A1 ⊙ SA)(W1 ⊙ SW)ᵀ` 可选，只在两者相交处执行；不重复计算前三项。
- 一阶方案的名义乘积倍率为 `1 + ρA + ρW`；交叉项另加实际相交比例。不是 `1 + ρAρW`，也不是延迟倍率。

激活块评分用 `E[(A−A0)²] × sum_N(W0²)`，再沿 K 块求和。权重块评分用 `E[A²] × (W−W0)²`，在 N128×K 块内求和。这是对输出误差收益的对角近似，忽略通道相关性和修复项之间的干扰，不是最优性证明。

NVFP4 的 scale 微块为 K16；SM120 原生 MMA 的一个 shape 是 M16N8K64。K128/256 是本实验的逻辑修复/执行分组，并非硬件唯一合法尺寸。[NVIDIA CUTLASS SM120 定义](https://github.com/NVIDIA/cutlass/blob/main/python/CuTeDSL/cutlass/cute/nvgpu/warp/mma.py)

本实验使用普通 `mma.sync` E2M1，在软件层跳过修复块，没有使用 `mma.sp` 2:4 稀疏指令，不能再套一个硬件稀疏峰值的 2× 倍率。K16 对照只有数值仿真，要实际执行还需 gather/重排为原生 K 粒度。

## 粒度与选块依据

下表为 18 组线性层输出相对原始 BF16 操作数 FP32 GEMM 的 pooled relative L2；同一表中 W0 固定。

| 激活修复 50% | 相对 L2 |
|---|---:|
| K16，在线残差加权，数值对照 | 0.056507 |
| K64，在线残差加权 | 0.057177 |
| K128，在线残差加权 | 0.057496 |
| K256，在线残差加权 | 0.057609 |
| K128，离线残差加权 | 0.057535 |
| K128，在线激活能量 | 0.057737 |

结论：K64 相比 K128 的 L2 改善约 0.55%，K256 相比 K128 的 L2 增加约 0.20%。离线排序比在线残差排序仅高约 0.067% L2；当前数据没有支持为这点增益支付每调用在线排序成本。默认可先冻结每层支持；未来用轨迹校准决定是否需要按 phase 切换，不能从这两条开发轨迹推断所有生成任务都适合固定支持。

先前“FFN 50%”实验主要是挑选部分整层开启修复；本次真正裁剪每个矩阵内部 K 通道块。两种 50% 的语义不同。

## 权重修复：等计算预算和低存储预算

| K128 方案 | 额外乘积倍率 | 相对 L2 |
|---|---:|---:|
| 无修复 | 0 | 0.067924 |
| A50% | 0.50 | 0.057496 |
| A43.75%＋W6.25% | 0.50 | 0.056719 |
| A37.5%＋W12.5% | 0.50 | 0.056271 |
| A25%＋W25% | 0.50 | 0.056107 |
| A75% | 0.75 | 0.052757 |
| A68.75%＋W6.25% | 0.75 | 0.051857 |
| A100%（full ACT2） | 1.00 | 0.047971 |
| A93.75%＋W6.25% | 1.00 | 0.046844 |

等乘积预算下，拿一点激活预算给权重残差有收益，但幅度有限。W25% 虽然局部误差更低，残差存储增加也更明显；低内存场景可优先把 W 控制在 3.125%–6.25%，6.25% 是本次已验证起点。

A75%＋W6.25% 的一阶方案为 0.050610；加交叉项为 0.050593，收益很小。先保留可选开关，默认关闭；不把微小局部收益等同于模型质量收益。

## 完整 FFN 回放

| 所有三个投影采用的方案 | pooled relative L2 |
|---|---:|
| W4A4，无修复 | 0.138585 |
| full ACT2 | 0.096040 |
| K128 A50% | 0.116884 |
| K128 A75% | 0.106627 |
| K128 A75%＋W6.25% | 0.103070 |

K128 A93.75%＋W6.25% 在 6/6 组输入上略优于 full ACT2，pooled L2 下降约 1.30%，总名义乘积数同为 2。K256 对应方案也在 6/6 组略优于 full ACT2，pooled 改善约 0.64%。

A75%＋W6.25% 的总乘积数为 1.8125，相比 full ACT2 的 2 减少 9.375%，但 K128 完整 FFN L2 高约 7.32%。不能称作“无损裁剪”，也未证明能还原 BF16 视频质量。

## 实际存储

本模型三个 FFN 投影的矩阵元素数相同：50,331,648。W0 的 FP4 codes＋K16 E4M3 scales 为 **27 MiB/矩阵**。

- W6.25% 的残差 codes＋scales 为 **1.6875 MiB/矩阵**。
- K256 的实际 CSR bank 包含 row offsets 和 block indices：gate 为 1,770,244 bytes，down 为 1,769,988 bytes，接近 1.688 MiB。
- 若全部 108 个 FFN 投影都使用 W6.25%，仅残差 codes＋scales 推算增加 **182.25 MiB**，再加少量索引；这是资产计算，不是全模型显存峰值测量。
- 每权重的 codes＋微块 scale 从平均 4.5 bits 增到约 4.78125 bits，未计小量全局 scale、prescale、metadata。

构造时暂时有全量 W0/W1，用于选择和离线打包；部署对象克隆 W0 并只保存被选 W1，需释放原准备张量。计时脚本为了比较保留多个候选银行，不能把其进程峰值当作单一部署 footprint。A 稀疏仍使用完整双平面 scratch 容量，producer 可跳过不需要的残差计算，但不会按稀疏比例减少 scratch 分配。

## Tensor Core 执行和性能

初版 native 先遍历全部稠密 K，再按索引遍历激活修复 K，最后遍历 W1 CSR。虽然减少分支检查，它会再次读取选中的 W0。改进版在同一个 K 循环里执行选中 A1W0，复用本次加载的 W0；W1 保持按 N 输出块的 CSR 索引执行。所有项共享一个 FP32 accumulator，最终一次缩放/写回。

下面为调优中三轮随机顺序测量的中位数，含在线 prescale/amax/量化/pack 和 GEMM；离线选块及 W 量化不计。共享负载造成明显方差，这些是观测值，不是独占卡 speedup 声明。

| 算子 | BF16 ms | K128 M32 融合 A50% | K256 M32 融合 A50% | K256 M64 full ACT2 |
|---|---:|---:|---:|---:|
| gate，M128/N12288/K4096 | 0.0927 | 0.0486 | 0.0745 | 0.0940 |
| gate，M512/N12288/K4096 | 0.3931 | 0.2749 | 0.2171 | 0.2434 |
| down，M128/N4096/K12288 | 0.0907 | 0.1744 | 0.1237 | 0.1713 |
| down，M512/N4096/K12288 | 0.2697 | 0.2978 | 0.2351 | 0.2694 |

例如 gate M128 K128 A50% 的三次值是 0.0486/0.0486/0.0859 ms；down M512 K256 A50% 为 0.2351/0.3266/0.2327 ms。不能只引用最好的比值。gate 的形状已有快于 BF16 的观测，down 小 M 仍明显落后，较大 M 的收益尚不稳。修复预算缩小也并不一定比 full ACT2 快。

M128 execution tile 虽通过当前数值验证，但调优结果没有支持它优于 M32/M64；attention 的 tile 限制不能直接套到 FFN。K64 在初版中比 K128/256 更慢；优先保留 K128/K256，再按 gate/up/down 和 M 的实际测量确定执行 tile。

## 推荐下一步

1. **质量优先起点**：K128、A93.75%＋W6.25%、关闭交叉项，离线残差加权选块。先与旧 full ACT2 做完整降噪轨迹对比，验证约 1% 的局部收益是否值得新增存储。
2. **预算起点**：K128 或 K256、A75%＋W6.25%；接受当前局部 FFN 相对 full ACT2 的质量退让后，再评估视频质量和端到端延迟。
3. **存储不增加**：只做 A75% 或 full ACT2；不引入 W1。K64/K16 细粒度目前没有足够收益来抵偿执行复杂度。
4. **实现重点**：继续融合 producer 的评分/packing、在完整网络图中复用 scratch；对 gate/up 共享输入的机会单独实现和测试；down 长 K 需要优化流水与权重读取。当前尚未实现 gate/up producer 共享或量化/GEMM overlap。
